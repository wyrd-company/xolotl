# Model metadata

The model catalog owns a validated projection of LiteLLM's registry and Codex's
native model entries. The existing catalog refresh cycle and manual refresh
update metadata. A failed fetch or validation keeps the last good registry and
its timestamp. SQLite stores the last good projection across restarts. Routing
works without metadata or network access.

LiteLLM's data source is
`https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json`.
Its registry schema is generated by
[`litellm-rust/crates/model-catalog/src/schema.rs`](https://github.com/BerriAI/litellm/blob/main/litellm-rust/crates/model-catalog/src/schema.rs).
The advertised `model_prices_and_context_window.schema.json` path is absent.
Xolotl validates the fields it consumes with a typed schema projection: registry
and entries must be objects, each entry must have a provider string, token
limits must be unsigned integers within signed 64-bit range, and prices must be
finite nonnegative numbers. Zero upstream token limits mean unknown. Other
upstream fields remain outside the projection; schema validation does not claim
to cover them. Configuration overrides require positive token limits.

Lookup tries `provider/model`, the mapped provider family, then the bare model.
Families are Codex→OpenAI, Claude→Anthropic, Grok→xAI, and OpenCode Go Qwen→DashScope.
An explicit `litellm_key` replaces automatic lookup. Each `catalog.metadata`
entry overlays only its supplied values. Missing limits and prices remain
unknown. The CLI and web UI expose the source key, last successful fetch age,
and refresh failure. Configuration-only values identify their override source.

Anthropic discovery adds `[1m]` only if every fallback target has a known input
limit of at least 1,000,000. Other model discovery keeps canonical names.
Messages routing and token counting strip the hint before policy lookup and
accounting. Upstreams receive the canonical target name. Recognized upstream
context errors become Anthropic `invalid_request_error` with `prompt is too long`,
including HTTP and translated streaming errors. Token estimates never reject
requests against inferred limits.

Translated Messages token counting uses serialized UTF-8 bytes divided by three,
rounded up, for system, messages, tools and tool choice. The response and header
identify it as an estimate. It makes no upstream request and incurs no usage
charge. Images and tokenizer-specific behavior prevent exact counting.

`GET` and `HEAD /backend-api/codex/models` use the same proxy-scope client-key
authentication and policy view as `/v1/models`. Browser session cookies do not
authorize it. Entries expose policy names and aliases which support Responses.
Native Codex fields are retained. Other entries use conservative capability
defaults and explicit tools, images and reasoning-level overrides. Alias context
uses the minimum of all known target windows; an unknown target leaves it
unspecified. Native Codex windows take precedence over LiteLLM unless configured.
Responses are private and not cacheable by intermediaries.

Accounting snapshots model prices at admission. The persisted API-equivalent
cost separates input, output, cache read and cache write tokens. Missing usage
or a required rate leaves cost unknown. Aggregates include priced-request counts
so partial coverage stays visible. These values represent API list-price value,
including subscription traffic; they do not represent billed spend. Existing
unpriced log rows remain unknown.
